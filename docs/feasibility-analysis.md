# Аналіз реалізованості ТЗ «AI-асистент для обробки звернень до адвоката»

Дата: 23.10.2026. Документ доповнює ТЗ від 17.10.2026: що з нього реально зробити силами одного адвоката (ФОП) з мінімальним бюджетом, від чого відмовитися і в якому порядку будувати.

> Цифри й тарифи взяті з відкритих джерел (посилання внизу). Перед будь-якою оплатою їх треба перевірити: умови сервісів змінюються.

## Коротко

| Що | Висновок |
|---|---|
| Канал для клієнтів | Тільки **Telegram** (безкоштовно). Viber і WhatsApp — можливе розширення в майбутньому |
| Де працює адвокат | **Одна веб-платформа** (сайт з логіном). Адвокату Telegram не потрібен |
| Де зберігаються дані | База даних платформи (SQLite). **Excel лишається** для перегляду і звітів: експорт у будь-який момент, початковий імпорт |
| Дія.Шеринг | **Не потрібен**: платний для бізнесу, а особу клієнта і так підтверджує КЕП/Дія.Підпис під договором |
| «Вчасно» | Реально (є API). Тариф і доступ до API уточнити. Безкоштовна альтернатива — підпис через id.gov.ua або паперовий договір |

| ЄДРСР, zakon.rada.gov.ua | Доступні. Посилання можна автоматично перевіряти, з ЄДРСР можна зібрати власний індекс рішень ВС з відкритих даних |

## 1. Канали звернень

### Telegram — єдиний канал на старті
Telegram Bot API безкоштовний, бот створюється за хвилини. Telegram використовують **лише клієнти**. Адвокат читає й відповідає у веб-платформі, а бот доставляє його відповіді клієнту в Telegram.

### Viber і WhatsApp — відкладено (можливе розширення)
- **Viber.** Боти, створені після 05.02.2024, працюють лише на комерційних умовах: близько **100 € на місяць за бота** плюс оплата за повідомлення, які надсилає бот. Для одного адвоката це невиправдано.
- **WhatsApp (Cloud API від Meta).** Абонплати немає, але потрібні акаунт Meta Business і окремий номер. З 01.10.2026 платними стали і відповіді у 24-годинному вікні після повідомлення клієнта. Джерела розходяться щодо безкоштовних 1000 повідомлень на місяць, тому для України тариф треба перевірити в Meta.
- Неофіційні бібліотеки (whatsapp-web.js, Baileys) **не радимо**: вони порушують правила WhatsApp, номер можуть заблокувати, а листування йде через неконтрольований код, що погано для адвокатської таємниці.
- Агрегатори (respond.io, SendPulse) платні й додають третю сторону в листування, тож вони не потрібні.

**Що робимо зараз.** Архітектура з ТЗ зберігається: усі повідомлення проходять через єдиний «модуль повідомлень». Тоді Viber чи WhatsApp пізніше додаються як ще один вхід, і агентів переробляти не доведеться. Поки що в профілі адвоката, на сайті й на візитці можна давати посилання «Написати асистенту в Telegram».

## 2. Платформа адвоката

### Одна веб-платформа
Це сайт з входом за паролем і двофакторною перевіркою (код у застосунку-автентифікаторі). Він відкривається з ноутбука й з телефона. На телефоні його можна «встановити» на головний екран як застосунок (PWA).

Розділи відповідають ТЗ:

| Розділ | Що там |
|---|---|
| **Дашборд** | Звернення колонками за статусами, термінові вгорі, прострочені червоним. Цифри за тиждень |
| **Чати** | Листування з клієнтами. Кнопка «Перехопити»: асистент замовкає, адвокат пише у вебі, клієнт отримує це в Telegram. Внутрішні нотатки, яких клієнт не бачить |
| **Пропозиції відповідей** | Картка справи, чернетка консультації, знайдені посилання. Кнопки «Затвердити й надіслати», «Редагувати», «Повернути з коментарем» |
| **Клієнти та договори** | Пошук клієнта, договори, оплати, документи, історія |
| **Зустрічі** | Календар із Google Calendar, перенесення й скасування |
| **Налаштування** | Шаблони повідомлень, анкети, переліки документів, строки, робочі години, адреса |

**Сповіщення** про термінові звернення (затримання, обшук тощо) приходять як push у браузер або на телефон і дублюються на email. Обидва способи безкоштовні.

### Де зберігаються дані: база даних і Excel

**Що таке база даних тут.** SQLite — це один файл на сервері платформи. Усередині ті самі «таблиці», що й в Excel, але з правилами:

| Таблиця | Що зберігає |
|---|---|
| `clients` | ПІБ, телефон, РНОКПП (видно лише адвокату), Telegram-контакт |
| `cases` | Звернення: статус, категорія, сторони, строки, складність |
| `messages` | Усе листування з клієнтом |
| `documents` | Файли, які надіслав клієнт |
| `drafts` | Чернетки консультацій: хто підготував, хто і коли затвердив |
| `meetings` | Зустрічі (синхронізовані з Google Calendar) |
| `payments` | Виставлені суми, призначення платежу, позначка «оплачено» |
| `audit_log` | Журнал: хто, коли і що відкрив чи змінив |

Адвокат цей файл не відкриває. Він бачить ці таблиці у платформі з пошуком, фільтрами й сортуванням. Postgres — те саме, тільки на окремому сервері бази; для одного адвоката SQLite достатньо, а перейти на Postgres пізніше нескладно.

**Excel лишається для зручності.**
- У розділах «Клієнти», «Справи», «Оплати» є кнопка **«Експорт в Excel»**: файл формується в будь-який момент з актуальними даними.
- Можна налаштувати автоматичний щотижневий експорт.
- Наявну таблицю клієнтів і справ **імпортуємо** під час запуску, щоб перевірка конфліктів одразу працювала по всій історії.

**Чому Excel не може бути «живою» базою, яку бот змінює напряму:**
1. **Одночасний запис.** Бот записує дані цілодобово: нові повідомлення, статуси, документи. Якщо адвокат у цей час тримає файл відкритим, бот або не зможе записати, або зміни затруть одна одну.
2. **Адвокатська таємниця.** В Excel немає журналу доступу і ролей. Файл легко скопіювати чи переслати, і ніхто про це не дізнається. ТЗ сам вимагає «доступ за ролями, журнал доступу, шифрування».
3. **Помилки в даних.** Дублікати клієнтів, ПІБ з одруківками, телефони в різних форматах ламають автоматичну перевірку конфліктів. База не дає зберегти такі дані.
4. **Обсяг.** Листування, файли й історію статусів у таблиці тримати незручно: за рік це десятки тисяч рядків.

Отже, база платформи — це джерело правди, а Excel — зручний звіт або копія.

## 3. Інтеграції

### Дія: Шеринг і Дія.Підпис — Шеринг прибираємо
- Для бізнесу Шеринг **платний**. Для банків оголошували близько 21,6 тис. грн за підключення і близько 9,8 грн за кожну операцію. Потрібні договір і технічна інтеграція з Мінцифри (integration.diia.gov.ua). Для одного адвоката це надмірно.
- **Шеринг не потрібен.** За ТЗ паспорт і РНОКПП потрібні лише для договору. Коли клієнт підписує договір КЕП або Дія.Підписом, у сертифікаті підпису вже є його ПІБ і РНОКПП, тобто особу підтверджує сам підпис.

### Вчасно.ЕДО — реально, але треба уточнити тариф
- Є API v2: токен створюється в налаштуваннях «Вчасно», є неофіційний Python SDK. Платформа надсилає договір і відстежує статус підписання.
- Клієнт-фізособа підписує договір КЕП або Дія.Підписом.
- **Уточнити у «Вчасно»:** скільки документів дає безкоштовний тариф, чи доступний на ньому API і чи має клієнт реєструватися, щоб підписати.
- **Безкоштовна альтернатива:** платформа надсилає PDF договору, клієнт підписує його на id.gov.ua (Дія.Підпис) і повертає файл підпису (.p7s/.asice), а платформа перевіряє підпис. Або договір підписують на папері під час зустрічі.

### Google Calendar API — безкоштовно
Окремий календар «Прийом» з робочими годинами, щоб асистент не бачив особистих подій. Адресу офісу й робочі години внесемо в налаштування пізніше.

### Оплата — переказ за IBAN на рахунок ФОП
- Бот надсилає реквізити: отримувач (ФОП), IBAN, РНОКПП, сума, призначення «Оплата за послуги згідно з договором № … від …».
- До реквізитів додається **QR-код платіжної інструкції за стандартом НБУ**. Клієнт сканує його в застосунку свого банку, і переказ заповнюється автоматично.
- Адвокат у платформі натискає «Оплату отримано», і статус справи змінюється.
- Це безкоштовно: без еквайрингу, комісій і інтеграцій.
- **Можливе розширення:** автоматичне підтвердження оплати через API банку (наприклад, webhook виписки monobank) або еквайринг (LiqPay, WayForPay, monobank, приблизно 1,3–2,5% комісії). Для еквайрингу з бухгалтером треба уточнити питання ПРРО (фіскальних чеків).

### База правових позицій Верховного Суду (lpd.court.gov.ua) — без API
- Ресурс безкоштовний і відкритий, реєстрація не обов'язкова.
- **Офіційного API немає.** Автоматично «збирати» сторінки (скрейпінг) ненадійно, бо ламається при кожній зміні сайту, і юридично сумнівно.
- **На старті:** Дослідник формулює ключові слова, норми й пошукові запити, а адвокат шукає в базі сам. Це займає кілька хвилин, а знайдені позиції адвокат вставляє в картку.

### ЄДРСР (reyestr.court.gov.ua) — доступно
- Рішення у вільному доступі. Набори відкритих даних ЄДРСР публікуються на data.gov.ua (наказ ДСА № 1120), їх дозволено вільно використовувати.
- **Реалістичний шлях (етап 2):** зібрати власний пошуковий індекс **лише рішень Верховного Суду** з відкритих даних. Дослідник шукає в ньому і дає посилання виду `reyestr.court.gov.ua/Review/<номер>`, а платформа автоматично перевіряє, що посилання відкривається. Це закриває ризик вигаданих посилань з ТЗ.

### zakon.rada.gov.ua — доступно
Тексти законів відкриті, є портал відкритих даних data.rada.gov.ua (умови доступу уточнити). Для старту достатньо посилань на статті з автоматичною перевіркою, що вони відкриваються.

### Claude API — «мозок» агентів
- Оплата за використання, орієнтовно центи за одне звернення.
- Персональні дані маскуються **до** відправки в модель: номери паспорта й РНОКПП замінюються на «***», як у ТЗ.
- ТЗ вимагає договору про обробку даних з постачальником ШІ. Для цього є комерційні умови й DPA Anthropic.

## 4. Технічна основа (для наступного етапу)

| Частина | Вибір |
|---|---|
| Мова | Python |
| Telegram-бот | aiogram 3 |
| Веб-платформа | FastAPI + серверні сторінки (Jinja2, htmx), без окремого фронтенду |
| База | SQLite (за потреби — Postgres) |
| ШІ | Claude API, окремий промпт і набір інструментів для кожного агента |
| Хостинг | VPS у ЄС, близько 5 $/міс, щоденні зашифровані бекапи |

## 5. Скоригований план етапів

1. **MVP.** Telegram-бот: Приймальник (згода, терміновий фільтр, верифікація ПІБ і телефону, опитування, документи) і Аналітик (картка справи). Веб-платформа: дашборд, чати з перехопленням, затвердження відповідей, клієнти, імпорт і експорт Excel. Перевірка конфліктів: точний збіг ПІБ, телефону чи ЄДРПОУ перевіряє код, неточні збіги підказує ШІ. Термінові звернення сповіщаються через push і email.
2. **Відповіді й зустрічі.** Дослідник з автоматичною перевіркою посилань, Координатор з Google Calendar, нагадування клієнту, сценарій «клієнт зник».
3. **Договір і оплата.** Договір через «Вчасно» або id.gov.ua, оплата за IBAN з QR-кодом НБУ, база клієнтів за договором.
4. **Можливі розширення.** Індекс рішень ВС з ЄДРСР, WhatsApp, Viber, еквайринг, автоматичне підтвердження оплат. Дія.Шеринг не потрібен.

## 6. Витрати і що уточнити

| Стаття | Орієнтовно на місяць |
|---|---|
| Telegram Bot API | 0 $ |
| Сервер (VPS) | ~5 $ |
| Claude API | кілька $, залежно від кількості звернень |
| Google Calendar API | 0 $ |
| Оплата за IBAN | 0 $ |
| «Вчасно» | за тарифом, уточнити |
| **Разом** | **≈ 5–15 $** |

**Уточнити:**
- **«Вчасно»:** ліміти безкоштовного тарифу, доступ до API, чи потрібна клієнту реєстрація для підпису.
- **Бухгалтер:** формулювання призначення платежу для ФОП.
